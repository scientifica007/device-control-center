# Device Control Center — مركز التحكم بالأجهزة

تطبيق سطح مكتب عربي RTL لمراقبة الأجهزة المرتبطة بحاسوب Ubuntu 24.04 LTS، مع التركيز على بطاريات Bluetooth، والصوت، والشبكات. الإصدار المرشح الحالي v0.1.11 (تسجيل تشخيصي اختياري)، بينما v0.1.10 هو آخر إصدار معتمد ميدانيًا. v0.1.10 لعرض الملف الصوتي والترميز النشط لبطاقات Bluetooth دون تغيير إعداداتها؛ v0.1.7 أصلح أشرطة التحكم؛ v0.1.6 ثُبّت على جهاز المستخدم وصحح التسميات؛ v0.1.5 ثُبّت واختُبر ميدانيًا في 29/10/2026، وv0.1.3 أساس مستقر سبق اعتماده.

## إصلاح v0.1.1

يصلح تعارض تحميل GDK 4 بدل GDK 3 في بدء التشغيل، ويضيف اختبار تشغيل GTK حقيقيًا باستعمال شاشة Xvfb افتراضية في GitHub Actions. لا يعني نجاح الاختبار تشغيلًا مثبتًا على حاسوب المستخدم؛ يجب تأكيد ذلك ميدانيًا. راجع `docs/CODEX_HANDOFF.md` لتفاصيل تسليم التجريب المحلي إلى Codex.

## الوظائف الحالية

- عرض أجهزة Bluetooth المعروفة وحالة الاتصال والاقتران والثقة، مع البحث اليدوي عن أجهزة قريبة.
- قراءة نسبة البطارية من BlueZ أو UPower عند توفرها؛ تم التأكد من إبلاغ سماعة Condor Aero 1 عن بطارية 70% في عينة المستخدم، وليس كقيمة ثابتة في التطبيق.
- عرض مؤشر RSSI عند توفره؛ عدم ظهور المؤشر لا يعني سوء الاتصال.
- اتصال وفصل الأجهزة ومحاولة الإقران؛ بعض حالات الإقران تتطلب موافقة في واجهة نظام التشغيل.
- اختيار مخرج الصوت والميكروفون، والتحكم في مستوى الصوت والكتم عبر PipeWire وWirePlumber.
- عرض شبكة Wi-Fi وإشارتها حين يعرضها NetworkManager.
- تحديث الحالة كل 12 ثانية، وتصدير تقرير JSON محلي.
- تنفيذ استعلامات الأجهزة في خيط خلفي حتى لا تتجمد واجهة GTK.

## التثبيت على Ubuntu 24.04 LTS

تنزيل حزمة DEB من نتيجة GitHub Actions، أو بناؤها محليًا:

    git clone https://github.com/scientifica007/device-control-center.git
    cd device-control-center
    bash packaging/build_deb.sh
    sudo apt install ./dist/device-control-center_0.1.11_all.deb

ثم تشغيلها من قائمة التطبيقات أو بالأمر:

    device-control-center

إزالة الحزمة:

    sudo apt remove device-control-center

## التحقق

    python3 -m unittest discover -s tests -v

تشغل GitHub Actions الاختبارات وبناء DEB على بيئة Ubuntu 24.04، وتتيح تنزيل الناتج كـ artifact عند اكتمال التشغيل. ينبغي اختبار واجهة GTK على جهاز فعلي أيضًا، لأن اختبارات المحللات لا تكافئ اختبار الأجهزة.

## ملاحظات مهمة

- مستوى ضبط الميكروفون ليس قراءة مستوى الإشارة الصوتية اللحظية.
- تقدير المسافة عبر Bluetooth غير متوفر في v0.1.1.
- نسبة البطارية لا تظهر إلا عندما يكشف الجهاز عنها.
- التطبيق لا يحتاج صلاحيات root في التشغيل المعتاد؛ ولا يرسل أي قياسات إلى الإنترنت.
- أرقام تعريف عقد الصوت تتغير، لذلك تُكتشف تلقائيًا عند التحديث.
- تطبيق الهاتف المرافق وتبادل الملفات والأوامر قيد التخطيط وليسا جزءًا من النسخة الحالية.

انظر docs/ROADMAP.md للخطوات المقبلة.

## v0.1.4 — أيقونة وهوية التطبيق

معالجة [المشكلة #1](https://github.com/scientifica007/device-control-center/issues/1): أيقونة SVG أصلية تمثل لوحة تحكم بالأجهزة، وتوحيد اسم الأيقونة واسم برنامج GTK وStartupWMClass مع ملف desktop. لم يتغير اسم الاختصار ولم تُعدّل واجهة التطبيق أو وظائف الأجهزة. أُعلن اعتماد librsvg2-common القياسي لضمان دعم SVG حتى دون توصيات GTK الاختيارية؛ هو متوفر أصلًا على جهاز الاختبار. جرى الاكتفاء بتصنيف Utility لتجنب تعدد التصنيفات الرئيسية.

نجح تصيير أيقونة الحزمة عند 16 و24 و32 و48 و128 بكسل، وفحص Wayland app_id وX11 WM_CLASS على سطح المكتب، دون تثبيت الحزمة الجديدة. بتاريخ 29/10/2026 ثبّت المستخدم v0.1.4 وأكد ظهورها في قائمة Ubuntu وDock، وأُغلقت المشكلة #1. لا يُنسب إليه اختبار Alt+Tab لم يصرّح به.

اختبار الحزمة دون تثبيتها (يتطلب شاشة فعلية أو Xvfb):

    /usr/bin/python3 tests/check_deb_icon.py dist/device-control-center_0.1.11_all.deb

## v0.1.5 — موثوقية غياب البطارية (#2)

التشخيص الحي أثبت غياب Battery1 وعدم وجود السماعة في UPower مع استمرار اتصالها في العينات، ثم عودة 90% إلى BlueZ وUPower وv0.1.4 نفسه، وظهور 100% في جولة لاحقة. لا دليل أن الأيقونة سببت الغياب أو أن هذه القيم تثبت خطوات إبلاغ ثابتة.

- قيمة البطارية الحالية تبقى غير متاحة عند غياب بيانات النظام؛ لا استعادة لرقم من جلسة سابقة.
- آخر قيمة معروفة أثناء الجلسة تظهر منفصلة بوسم «قديمة»، دون شريط تقدم أو تنبيه شحن منخفض لها.
- وقت آخر محاولة فحص منفصل عن وقت آخر رصد ناجح؛ وقت إبلاغ الجهاز غير مفترض.
- فشل جهاز UPower واحد لا يمنع قراءة الأجهزة التالية، والقراءة البديلة الناجحة لا تُسقط عند فشل استعلام حالة Bluetooth.
- لا تغيير لمعدل التحديث البالغ 12 ثانية، ولا أوامر إعادة اتصال أو تبديل ملفات.

راجع [التحقق الميداني](docs/LOCAL_VALIDATION.md) و[دراسة الشريط العلوي](docs/TOP_BAR_STUDY.md). لم تُنفّذ ميزة الشريط ولم تُثبّت v0.1.5؛ السبب العميق لتقطع إبلاغ السماعة في خدمات النظام ما زال غير محسوم.

## GNOME 46: نموذج أولي منفصل للشريط العلوي (غير مثبت)

تمت إضافة تجربة اختيارية لا تتطلب تشغيل نافذة التطبيق. تقرأ BlueZ وUPower بواسطة D-Bus وتعرض نسبة الجهاز المتصل أو علامة «—» عند غياب القراءة، بلا استطلاع دوري أو اتصال أو فصل تلقائي. لم تُختبر بعد داخل GNOME Shell الفعلي، ولا تُثبَّت مع حزمة v0.1.5.

ملفات المصدر وتعليمات البناء والتراجع موجودة في [gnome-extension/README.md](gnome-extension/README.md). تتوفر الحزمة التجريبية ZIP ضمن GitHub Actions بعد نجاح الفحوصات. لا تضف الامتداد إلى بيئة GNOME اليومية قبل الاختبار والموافقة الميدانية.

## v0.1.6 — توضيح قوة الإشارة

- فصل نص «قوة إشارة Bluetooth (RSSI)» داخل بطاقة الجهاز عن «قوة إشارة Wi-Fi» داخل قسم الشبكة؛ الوحدات مختلفة وليستا قراءتين لنفس الرابط.
- Bluetooth RSSI عند توفرها بوحدة dBm، وليست نسبة مئوية؛ غيابها لا يعني ضعف الصوت أو الاتصال.
- Wi-Fi SIGNAL نسبة يعرضها NetworkManager. إذا لم يوفر قياسًا، تظهر «غير متاحة» بدل «None%».
- لا مسح دوري جديد ولا تغيير في ربط الأجهزة أو ملف الصوت SBC ولا في عمل امتداد GNOME.
- تفاصيل حدود القياس وبدائل البحث في [docs/SIGNAL_METRICS.md](docs/SIGNAL_METRICS.md).
- **v0.1.6 غير مثبّت أو مختبر ميدانيًا حتى الآن**؛ البناء الآلي لا يغني عن تجربة المستخدم.

## v0.1.7 — عدم تغيير الصوت أثناء تمرير الصفحة

- تمرير عجلة الفأرة أو حركة الإصبعين فوق شريطي إخراج الصوت والميكروفون يحرك محتوى النافذة بدل تغيير مستوى الصوت بلا قصد.
- يظل ضبط المستوى المباشر بالسحب أو بلوحة المفاتيح متاحًا كما كان.
- يشمل الاختبار الاتجاهين والحركات السلسة والحدود العليا والدنيا للتمرير، ويراقب عدم تنفيذ أوامر كتابة الصوت عند التمرير.
- لا تغيير لترميز SBC أو إعدادات Bluetooth أو امتداد GNOME. يلزم اختبار ميداني على Wayland قبل اعتماد الإصدار.

## v0.1.8 — تمرير الصفحة فوق قوائم اختيار الصوت

- أصبح تمرير عجلة الفأرة أو لوحة اللمس فوق قائمتي «جهاز إخراج الصوت» و«جهاز إدخال الصوت / الميكروفون» يُحرّك الصفحة بدل التقاط الحركة داخل القائمة أو تغيير الجهاز.
- لا تتغير الأجهزة المختارة إلا باختيار مقصود من القائمة؛ لا يتغير سلوك فتح القوائم بالنقر أو تشغيل شريطي الصوت.
- اختبار GTK مع بيانات اصطناعية يؤكد حركة الصفحة وعدم تعديل الأجهزة عبر حدث scroll-event على كلتا القائمتين.
- لا حاجة إلى تعطيل امتداد البطارية في الشريط العلوي ولا إلى تغيير ملف SBC. يلزم اختبار Wayland الحقيقي قبل الاعتماد.

## v0.1.9 — إصلاح جذري لتمرير الصفحة فوق اختيار الصوت

- أثبت الاختبار الميداني أن محاولة اعتراض `scroll-event` على `Gtk.ComboBoxText` في v0.1.8 لم تكن كافية على Wayland.
- استُبدلت القائمتان بـ `Gtk.MenuButton` يفتح `Gtk.Popover` للاختيار الصريح؛ التحريك بعجلة الفأرة فوق زر الاختيار المغلق لا يبدّل الجهاز.
- بقيت عناصر الاختيار والاختبار المباشر للتحكم في الصوت دون تغيير في الوظائف، ويظل امتداد GNOME منفصلًا.
- أُضيف اختبار Xvfb يحرك عجلة فأرة اصطناعية فعليًا بواسطة XTEST/xdotool فوق الزرين، إضافة إلى اختبار وظائف الاختيار. لا يُعد ذلك دليل قبول نهائي في Wayland.

## v0.1.10 — تشخيص ملف صوت Bluetooth

- يعرض ملف الصوت النشط من pactl لكل بطاقة Bluetooth صوتية، مثل A2DP / SBC أو A2DP / SBC-XQ.
- لا يستنتج الترميز من الملفات المتاحة وحدها، بل من وصف الملف النشط فقط، ويظهر «غير محدد من النظام» عند غياب التفاصيل.
- عند SBC-XQ يعرض تنبيه توافق دون أي تغيير آلي في الملفات.
- فشل pactl معزول عن قراءة wpctl والتحكم في الصوت.
- لا تغييرات في امتداد GNOME أو Bluetooth أو WirePlumber. بيانات الصوت الجديدة تدخل في تصدير JSON المحلي.
- يتطلب قبولًا ميدانيًا على Wayland.


## v0.1.11 — سجل تشخيص زمني اختياري (مرشح للاختبار)

- زر «بدء التسجيل» و«إيقاف التسجيل» في التذييل؛ معطل افتراضيًا، ولا يثبت خدمة أو يشغل برنامجًا عند بدء النظام.
- يستهلك نتائج الفحص الحالية كل 12 ثانية، دون استعلامات إضافية، ويسجل تغيرات الحالة ونقطة تحقق أولى ثم كل خمس دقائق (JSONL).
- يفصل بين البيانات المتاحة والقديمة وغير المتاحة والأخطاء؛ ولا يدعي معرفة وقت قياس البطارية داخل السماعة.
- إزالة أسماء الأجهزة وعناوين MAC وSSID ورسائل أخطاء الأدوات من السجلات، واستخدام معرّفات مؤقتة للجلسة فقط.
- الكتابة في خيط مستقل إلى `$XDG_STATE_HOME/device-control-center/diagnostics/` أو `~/.local/state/device-control-center/diagnostics/`، بصلاحيات خاصة، وحد 5 MiB للجلسة و25 MiB للإجمالي و7 أيام للاحتفاظ.
- لا مسح Bluetooth تلقائي أو تبديل ترميزات/ملفات صوت، ولا تسجيل ميكروفون أو إرسال بيانات.
- **v0.1.11 غير مثبت ولم يُعتمد ميدانيًا**؛ آخر نسخة معتمدة على HP 630 هي v0.1.10. راجع [المعمارية](docs/DIAGNOSTICS_DESIGN.md) و[التحقق](docs/LOCAL_VALIDATION.md).


## v0.1.12 — عدّاد مدة التسجيل والإيقاف التلقائي

- يظهر عداد زمني محدث كل ثانية أثناء التسجيل في التذييل، ويُحفظ وقت انتهاء الجلسة عند الإيقاف؛ لا يعتمد على تغيّر ساعة النظام.
- حقل «مدة التسجيل بالدقائق (0 = دون حد)» يسمح بقيمة 0 (تسجيل مفتوح حتى الإيقاف اليدوي)، أو من 1 إلى 1440 دقيقة (24 ساعة كحد أقصى). اضبطه **قبل** النقر على «بدء التسجيل»؛ يتعطل أثناء الجلسة وتُستخدم القيمة المحددة للجلسة الجديدة فقط.
- يعمل الإيقاف التلقائي في خيط محرك التسجيل نفسه حتى إذا لم تصل أي قراءات جديدة أو تأخرت واجهة GTK. تبقى هناك إمكانية الإيقاف اليدوي أو إغلاق التطبيق في أي وقت.
- السجل JSONL يتضمن في session_start الحقل duration_seconds (null عند عدم التحديد)، وفي session_end حقل reason يميز بين manual وduration_elapsed وwindow_closed؛ يدعم هذا الاستخدام المخرجات السابقة ولا يغيّر التسجيل الأساسي.
- **v0.1.12 مرشح جديد**: لا يغيّر الصوت أو امتداد GNOME، ويحتاج اختبارًا ميدانيًا بعد نجاح CI. تقرير «تصدير JSON» التقليدي مختلف عن JSONL التشخيصي وقد يحتوي أسماء الشبكات وعناوين الأجهزة؛ لا تنشره دون مراجعة.

## v0.1.13 — وصول واضح إلى تقارير JSON وJSONL

- التقارير الجديدة تُحفظ في مجلد واحد ظاهر داخل «المستندات»: `<Documents>/Device-Control-Center/Reports/`. يستعمل التطبيق مجلد المستندات الفعلي حسب `xdg-user-dir DOCUMENTS`، مع الرجوع إلى `~/Documents` عند عدم توفره.
- زر **«فتح مجلد التقارير»** بجوار «تصدير تقرير JSON» يفتح المجلد مباشرة عبر مدير الملفات الافتراضي، ولا يجري فحصًا للأجهزة.
- تبدأ نافذة «تصدير تقرير JSON» داخل المجلد ذاته، باسم يتضمن وقت الحفظ؛ يمكن للمستخدم اختيار مسار آخر يدويًا، وحينها لا ينتقل الملف إلى مجلد التقارير الموحد.
- تحفظ جلسات JSONL الجديدة تلقائيًا في هذا المجلد المشترك. يبدأ التسجيل ويُوقف من الزر المعتاد، وتظل الحدود 5 MiB للجلسة / 25 MiB إجمالًا وحذف ملفات JSONL التي تجاوزت 7 أيام **عند بدء جلسة جديدة**. لا تُحذف ملفات JSON العادية بسبب تنظيف JSONL.
- يبقى المجلد المشترك خاصًا بالمستخدم (`0700`)، وتُنشأ ملفات JSON وJSONL الجديدة بصلاحيات `0600`. **ملفات JSON العادية ليست مجهولة الهوية** وقد تتضمن MAC وSSID؛ وتبعًا لإعدادات نظامك قد يُزامَن مجلد «المستندات» بواسطة أدوات أخرى. لا يرفع التطبيق أي شيء تلقائيًا.
- السجلات القديمة الموجودة تحت `~/.local/state/device-control-center/diagnostics` تبقى في مكانها، ولا يحاول التطبيق نقلها أو تغيير صلاحياتها تلقائيًا. يبقى ذلك المسار قابلًا للفتح يدويًا.
- أصلح إدخال تردد Wi-Fi بصيغة `2447 MHz` إلى الحقل الرقمي `frequency_mhz` في السجل الجديد؛ القيمة كانت مفقودة في سجل التجربة السابقة، دون أي تقدير تردد بديل.
- هذا الإصدار يحتاج اختبارًا ميدانيًا، ولا يغير SBC أو الصوت أو امتداد GNOME.
